# Kairo development timeline

This document records Kairo's product development in chronological order. Feature work and bug
fixes have separate timelines so readers can follow each without mixing product changes with
repairs.

The detailed record starts with the Kairo product work in June 2026 and continues through the
current branch on August 23, 2026. Kairo inherited its earlier foundation from T3 Code. That
foundation includes the Electron monorepo, provider adapters, event-sourced server, WebSocket
protocol, Git worktrees, checkpoints, diffs, terminals, web client, desktop client, and mobile
client. The upstream repository contains the commit-level history for that work.

Merge commits are omitted unless they mark an upstream sync. Refactors and release work appear in
their own section. Commit links point to the Kairo repository.

## Upstream fixes retained in Kairo

The August 22 upstream sync also carried fixes that users see in Kairo. The main groups were:

- terminal stability, character encoding, clipboard behavior, and mouse-motion performance;
- thread ordering, pinned-thread drag behavior, stream following, and sidebar provider icons;
- oversized thread-search and terminal-grapheme crash prevention;
- composer spacing, banner overlap, launcher shortcuts, and file-path tooltips;
- provider session recovery, Cursor defaults, legacy model filtering, and server UTF-8 headers;
- safer desktop deep links, HTTPS clone defaults, and longer worktree creation timeouts.

The sync landed in [`4c1c20a`](https://github.com/Saikrishna-Ambeti/kairo/commit/4c1c20a).
Individual upstream commits keep their original pull request numbers in `git log`.

## Current product state

As of August 23, 2026, Kairo has:

- web, desktop, iOS, and Android clients for local and remote environments;
- Codex, Claude, Cursor, Grok Build, and OpenCode provider adapters;
- Build, Plan, and student-focused Study interaction modes;
- optional hosted memory with account-based Kairo Cloud provisioning;
- connected-app settings, guided onboarding, and profession selection;
- Git, worktree, terminal, checkpoint, diff, and pull-request workflows;
- local student routine drafts in the web client;
- Kairo-branded marketing, release assets, and client shells.

For user instructions, start at the [documentation index](../README.md). For the behavioral Kairo
patch retained across upstream syncs, read [Kairo Patch](../project/PATCH.md).
