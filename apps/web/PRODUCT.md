# Kairo web product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Kairo users run coding agents against projects on local or remote environments. Students are an
identified role and need generated documents to remain easy to find after a thread ends.

## Product purpose

Kairo gives users a minimal interface for directing coding agents and reviewing their work across
durable project threads. Success means users can move between threads, environments, and generated
work without losing context.

## Positioning

Kairo connects to provider CLIs that users already subscribe to. One Kairo environment owns its
projects, threads, files, provider credentials, and runtime state. Web, desktop, and mobile clients
can connect to that environment locally or remotely.

## Operating context

Users work inside project threads. Agents can create files in project workspaces. The right panel
hosts task-specific views such as Browser, Files, and Agents. Global navigation includes Usage.

Document artifacts are `.docx` and `.pdf` files generated by an agent. A thread-level Artifacts
view shows documents from the active thread. A Library view searches document artifacts generated
across every project and thread in the current Kairo environment.

## Capabilities and constraints

- Kairo supports web, desktop, and mobile clients. Desktop wraps the web client.
- Remote, relay, and tunnel connections must not expose workspace files through unsigned URLs.
- Artifact metadata belongs to the environment that owns the files.
- Library scope is the current environment, not every connected environment.
- Search must use indexed metadata instead of rescanning every workspace on each query.
- Agents choose artifact titles and filenames from the user's ordinary prompt. Kairo does not ask
  for a separate title or document form.

## Product principles

- Keep agent work inside normal threads instead of creating a parallel document workflow.
- Make generated files visible after the conversation that created them.
- Keep remote behavior equivalent to local behavior.
- Prefer small typed contracts over client-only state.
